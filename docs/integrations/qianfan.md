# 接入百度智能云千帆（Qianfan）

> ## ⚠️ 隐私提示（接入前必读，本平台条款需特别注意）
>
> **对数据的承诺（相对强）**：用户协议 5.1(6)「我们**不会使用您的输入和模型输出数据、
> 上传的知识文档、数据集进行训练**，也不会将您的数据集与任何第三方共享」；隐私政策
> 「原则上存储在**中华人民共和国境内**」，跨境需单独同意。
>
> **但有三个「但是」，接入前务必知情**：
>
> 1. 协议 13.2 授权平台将数据用于「性能优化 / 故障排查 / 风控」；
> 2. 协议明确「**您不得向本服务提供保密信息……我们没有保密义务**」；
> 3. 平台把**「取得最终用户同意」的责任全部压给开发者**。
>
> ⚠️ **特别注意**：`analyze_jobs_batch` 会把整批职位数据（可能含招聘方联系人、薪资等
> 个人信息）送进模型上下文。若用于对外产品，请自行完成合规评估与告知同意。
>
> 数据流向：`千帆 → 你的 MCP 端点 → LLM 厂商`。完整对照见 [`PRIVACY.md`](PRIVACY.md)。

## 1. 支持情况（本平台限制最多，先看这一节）

| 项 | 结论 |
|---|---|
| 是否支持 MCP | ✅ 支持，但**只在工作流节点**：创建 → 工作流 Agent/组件 → 节点「工具引入 → **MCP Server**」→ 配置 |
| 传输方式 | 🔴 **只支持 SSE，不支持 Streamable HTTP** |
| 配置字段 | JSON 编辑器，模板 `{"mcpServers":{"serverName":{"url":"your server url"}}}` —— **没有 `type`、没有 `headers`** |
| 鉴权 | 🔴 **只能把凭据放进 URL 查询串**（官方示例一律如此：`?ak=`、`?api_key=`） |

**因此接千帆时，服务端地址要填 SSE 端点，令牌走查询串：**

```
https://<你的域名>/sse?token=<你的访问令牌或 LLM Key>
```

> 这正是 JobCopilot 同时提供 `/sse` 与 `?token=` 兜底的原因——不是因为偏好，
> 而是千帆的配置结构决定了它只能这么接。

> ℹ️ 平台内还有「自主规划 Agent → 能力扩展-组件 → MCP-SSE 组件」，但那是从**广场**
> 挑选平台内建服务，**不能填任意自建 URL**。广场只接受上架组件/云函数形式的 MCP。

## 2. 替代路线

| 路线 | 说明 |
|---|---|
| **API 节点** | 手动填或 **cURL 一键导入**（不是 OpenAPI 文件）；参数层级 ≤ 10 层、返回内容 ≤ 1M、支持流式 |
| **函数计算 CFC 节点** | ⚠️ 超时口径「通常 **10 秒**」——`analyze_jobs_batch` 基本不可能在 10 秒内完成，不建议 |
| 旧 `ai-plugin.json` / OpenAPI 文件导入 | ⛔ **已于 2024-07-31 随「插件编排」下线，不要按那套做** |

## 3. 本平台特有的坑

1. **返回体 ≤ 1M**（API 节点硬限）。批量市场报告的完整 JSON 有超限风险 → 控制单次
   职位数量。
2. **工作流 MCP 节点一次只能选一个工具**（跟百炼一样）。
3. **公网/VPC/来源 IP 白名单：官方文档未写**。按「必须公网可达」准备。
4. **不要假设高德/CFC 之外的长任务支持**——10 秒超时口径对批量分析是硬伤。

## 4. 另一条路：百度 AI 原生网关（AIGW）

百度另有一个独立产品 **AI 原生网关 AIGW**（2026-01-01 公测），表单里明确有
**「MCP 协议类型：Streamable HTTP」+「直接代理」**模式，可以直连原生 MCP 服务
（还支持自定义 header 名做鉴权、公网 + VPC 双入口）。

❓ **但「AIGW 托管的 MCP 能否被千帆 AppBuilder 消费」官方未写明**——走这条路必须
实测或开工单确认。若成立，它比工作流 MCP 节点更完整。
