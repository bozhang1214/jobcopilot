# 数据流向与隐私说明

> 本文回答一个问题：**用 JobCopilot 分析一段 JD 时，这段 JD 到底会经过哪些地方？**
>
> 结论先行：**无论哪种接入方式，JD 正文都会发给 LLM 厂商**（除非你用本地模型）。
> 接入方式决定的是「除 LLM 厂商之外，还有谁看得见」。

---

## 1. 三种接入拓扑

| | A · stdio 本地 | B · 自建 HTTP | C · 云端平台 |
|---|---|---|---|
| 典型客户端 | DSH / Claude Desktop / Cursor | 你自己的应用、内部系统 | 扣子 / 百炼 / 千帆 / HiAgent / Dify |
| JobCopilot 进程跑在哪 | **你的机器** | 你的服务器 | 你的服务器（平台通过 HTTPS 调用） |
| 平台上是否留痕 | 否 | 否 | **是**（平台会保存对话/调用记录） |
| JD 是否经过第三方服务器 | 否 | 否 | **是**（平台方的服务器） |
| 隐私等级 | 最高 | 高 | 中 |
| 适合的 JD | 任意，含内部未公开职位 | 任意，含内部未公开职位 | 公开职位、已脱敏职位 |

「三方当事人」分别是：

1. **你**（客户端 + 服务端）；
2. **LLM 厂商**（DeepSeek / 通义 / 月之暗面 / 豆包 / 智谱 / OpenAI）——接收提示词与 JD 正文；
3. **云端平台方**（仅 C 拓扑）——JD 先到平台，再由平台调用你的 MCP 端点。

---

## 2. 逐项说明

### 2.1 永远会离开你机器的东西：发给 LLM 厂商的内容

内核的工作方式是「把提示词 + JD 拼起来交给模型」。所以下列内容会发给你配置的
LLM 厂商，**任何拓扑都一样**：

- JD 正文（`jd_text`，或 `source_path` 读到的文件内容）；
- 你的**求职者画像**（若已 `save_profile` 或按请求注入 `user_profile`）；
- JobCopilot 的提示词文本。

不想让 JD 离开本机 → 只能换成**本地部署的模型**（把 `JOBCOPILOT_LLM_PROVIDER`
指向 OpenAI 兼容的本地推理服务）。项目本身不内置本地模型。

> 「Key 不落盘」指的是**你的 API Key**：它只在环境变量 / 请求头里传递，不写文件、
> 不进代码仓库。这不等于「数据不出本机」。

### 2.2 JobCopilot 服务端自己怎么处理数据

- **不持久化 JD**：分析是一次性的，JD 不写数据库、不落日志正文；
- **画像**：`save_profile` 会把画像写到 `JOBCOPILOT_DATA_DIR`（默认 `~/.jobcopilot/profile.txt`）。
  多用户共用一台服务时**不要**使用 `save_profile`，改用按请求注入的 `user_profile` 参数，
  否则后一个人的分析会带上前一个人的画像；
- **提示词**：`sync_prompts` 会把提示词复制到本机目录（便于热改），不含任何个人数据；
- **本地提示词目录**（`JOBCOPILOT_PROMPTS_DIR`）优先级最高，可由宿主热改。

### 2.3 HTTP 形态额外要考虑的

- **按请求传 Key（BYOK）**：调用方带 `X-JobCopilot-Api-Key` 时，该 Key 只用于本次
  请求的 LLM 客户端，服务端不保存；进程内按 Key 的短哈希做 LRU 缓存（上限 32 个），
  重启即清空。**不要**把 Key 写进 URL 查询串（会进访问日志）。
- **`source_path` 默认禁用**：HTTP 形态面向「别人的服务器 + 多用户」，开放任意路径
  读取等于暴露宿主机文件系统。确需启用要显式设 `JOBCOPILOT_ALLOW_SOURCE_PATH=1`，
  并强烈建议用 `JOBCOPILOT_SOURCE_ROOT` 限定可读目录。
- **访问令牌**：`JOBCOPILOT_HTTP_TOKEN` 保证只有持令牌的调用方能使用该端点；
  未设令牌时程序**拒绝**在非回环地址上启动。
- **务必用 HTTPS**：MCP 客户端普遍要求 `https://`，且明文 HTTP 会让 JD 与
  `Authorization` 令牌在链路上可被读取。生产环境请用反向代理（nginx 等）终结 TLS。
- **访问日志**：反向代理会记录 URL 与方法。JD 在请求体里，通常不进访问日志；
  但**不要把敏感内容放进 URL**。

## 3. 给不同场景的建议

| 场景 | 建议 |
|---|---|
| 分析公司内部未公开职位 | 用 **A（stdio 本地）**，并确认 LLM 厂商的数据条款可接受 |
| 团队内多人共用一台分析服务 | 用 **B（自建 HTTP）**，开访问令牌 + HTTPS；每人带自己的 Key |
| 面向公开职位、要借平台流量 | 用 **C（云端平台）**，但先脱敏（去掉公司真名、薪资细节、联系方式） |
| 数据完全不能出本机 | 换本地模型；或只让 JobCopilot 做**提示词与结构化**部分，由你自管模型调用（`LLMPort` 可注入） |

---

## 4. 各平台的具体情况

云端平台侧的留存与合规条款由**平台方**决定，不在本项目控制范围内。逐个平台的
接入方式、调用链路与需要向使用者说明的事项见同目录下的平台文档：

- `coze.md` · 扣子
- `bailian.md` · 阿里云百炼
- `qianfan.md` · 百度智能云千帆
- `hiagent.md` · 火山引擎 HiAgent
- `dify.md` · Dify

> 这些文档在接入时**必须**包含一句明确提示：**数据会经过平台方服务器，隐私等级
> 低于本地 stdio 模式**。
